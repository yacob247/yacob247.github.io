================================================================================
 SPECIAL-FILES-REFERENCE.TXT
 Every "special file" a website can have — sitemaps, ads.txt, robots.txt,
 PWA files, security files, host configs, feeds, error pages, misc.
 --------------------------------------------------------------------------------
 Each entry gives you:
   · WHERE IT GOES  (exact folder / URL path)
   · FORMAT         (file type)
   · STRUCTURE      (annotated template you can copy)
   · NOTES          (gotchas)

 This is NOT a template you fill in once. Pick what applies to your site.
================================================================================


================================================================================
 SECTION 0 · WHERE FILES LIVE ON A SERVER
================================================================================

DOMAIN ROOT  →  https://example.com/  (the folder mapped to the domain)

   /                            ← ROOT
   ├── index.html               ← home page
   ├── about.html
   ├── contact.html
   ├── ...
   │
   ├── robots.txt               ← MUST be at root
   ├── sitemap.xml              ← MUST be at root (or referenced from robots.txt)
   ├── sitemap-index.xml        ← optional alternate name
   ├── sitemap.html             ← human-readable; can live anywhere
   ├── ads.txt                  ← MUST be at root (or /public_html)
   ├── app-ads.txt              ← MUST be at root
   ├── humans.txt               ← MUST be at root
   ├── security.txt             ← root OR /.well-known/security.txt
   ├── opensearch.xml           ← root or /search/
   ├── rss.xml                  ← root (or /feed/, /rss/)
   ├── atom.xml
   ├── feed.json
   ├── favicon.ico              ← root
   ├── browserconfig.xml        ← root
   ├── manifest.webmanifest     ← root (or /assets/)
   ├── service-worker.js        ← root (or /assets/) — scope matters
   ├── .htaccess                ← Apache only, root or per-folder
   ├── web.config               ← IIS only
   ├── _headers                 ← Netlify / Cloudflare Pages
   ├── _redirects               ← Netlify / Cloudflare Pages
   ├── netlify.toml             ← Netlify
   ├── vercel.json              ← Vercel
   ├── firebase.json            ← Firebase
   ├── CNAME                    ← GitHub Pages
   ├── .nojekyll                ← GitHub Pages
   │
   ├── .well-known/             ← EXACT folder name, all lowercase, hidden
   │   ├── security.txt
   │   ├── change-password
   │   ├── gpc.json
   │   ├── dnt-policy.txt
   │   ├── apple-app-site-association
   │   ├── assetlinks.json
   │   └── (others)
   │
   ├── assets/  (or /static/, /public/, /img/, /css/, /js/)
   │   ├── favicon-16.png
   │   ├── favicon-32.png
   │   ├── apple-touch-icon.png
   │   ├── icon-192.png
   │   ├── icon-512.png
   │   └── ...
   │
   ├── 404.html                 ← root or per-host
   ├── 500.html
   ├── offline.html
   ├── maintenance.html
   ├── coming-soon.html
   │
   ├── README.md                ← not served (hidden by web servers)
   ├── LICENSE
   ├── .gitignore
   └── ... actual site folders

RULES OF THUMB
  · Files starting with "." are hidden on most OSes and NOT served by most
    web servers by default (.htaccess, .well-known contents, .env).
  · robots.txt, sitemap.xml, ads.txt MUST be at the true root.
  · .well-known must be spelled exactly and be served with Content-Type.
  · Server config files (.htaccess, _headers, etc.) are read at deploy,
    not sent to visitors.
  · Every path in this document is relative to the DOMAIN ROOT unless
    marked otherwise.


================================================================================
 SECTION 1 · SEARCH ENGINE / DISCOVERY FILES
================================================================================

--------------------------------------------------------------------------------
 1.1  robots.txt
--------------------------------------------------------------------------------
WHERE   : /robots.txt  (root, exact name, lowercase)
FORMAT  : plain text, UTF-8
SERVED  : Content-Type: text/plain
NOTES   : Crawlers fetch this first. Keep it small, don't hide secrets here
          (it's public). Use sitemap reference at the end.

STRUCTURE
  -------------------------------------------------------------------------
  # Group for general crawlers
  User-agent: *
  Allow: /              ← allow everything
  # Disallow: /admin/   ← block a folder (optional, one per line)
  # Disallow: /*.pdf    ← block a pattern (optional)

  # Block a specific bad crawler
  # User-agent: BadBot
  # Disallow: /

  # Crawl delay (seconds; only some bots honour it)
  # Crawl-delay: 5

  # Sitemaps — absolute URL, one per line
  Sitemap: https://example.com/sitemap.xml
  # Sitemap: https://example.com/sitemap-images.xml
  # Sitemap: https://example.com/sitemap-videos.xml
  -------------------------------------------------------------------------

MUST NOT contain: passwords, admin paths you're trying to hide, staging URLs,
                  crawl-delays on Googlebot (ignored), inline comments after
                  rules on the same line without care.


--------------------------------------------------------------------------------
 1.2  sitemap.xml
--------------------------------------------------------------------------------
WHERE   : /sitemap.xml  (root, exact name)
FORMAT  : XML
SERVED  : Content-Type: application/xml
NOTES   : Up to 50,000 URLs per file, 50 MB max uncompressed. If bigger,
          split into multiple sitemaps and use a sitemap-index (1.3).

STRUCTURE
  -------------------------------------------------------------------------
  <?xml version="1.0" encoding="UTF-8"?>
  <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">

    <!-- ===== HOME ===== -->
    <url>
      <loc>https://example.com/</loc>
      <lastmod>2025-01-15</lastmod>
      <changefreq>weekly</changefreq>
      <priority>1.0</priority>
    </url>

    <!-- ===== TOP-LEVEL PAGES ===== -->
    <url>
      <loc>https://example.com/about</loc>
      <lastmod>2025-01-10</lastmod>
      <changefreq>monthly</changefreq>
      <priority>0.8</priority>
    </url>

    <url>
      <loc>https://example.com/contact</loc>
      <lastmod>2025-01-10</lastmod>
      <changefreq>yearly</changefreq>
      <priority>0.6</priority>
    </url>

    <!-- ===== BLOG / CONTENT ===== -->
    <!-- repeat this block for every URL you want indexed -->
    <url>
      <loc>https://example.com/blog/my-post</loc>
      <lastmod>2025-01-14</lastmod>
      <changefreq>monthly</changefreq>
      <priority>0.7</priority>
    </url>

  </urlset>
  -------------------------------------------------------------------------

FIELD CHEATSHEET
  <loc>          absolute URL, no fragments (#), no querystring unless real
  <lastmod>      W3C date (YYYY-MM-DD or full ISO-8601). Omit if unsure.
  <changefreq>   always | hourly | daily | weekly | monthly | yearly | never
                 (Google mostly ignores this — set to "weekly" or omit)
  <priority>     0.0 – 1.0  (relative to other URLs on YOUR site, not global)
                 Home=1.0, key pages=0.8, deeper=0.5–0.6, old=0.3


--------------------------------------------------------------------------------
 1.3  sitemap-index.xml
--------------------------------------------------------------------------------
WHERE   : /sitemap-index.xml  (reference it from robots.txt)
FORMAT  : XML
WHEN    : Your sitemap has > 50k URLs, or you have separate sitemaps for
          images / videos / news / categories.

STRUCTURE
  -------------------------------------------------------------------------

  <sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
    <sitemap>
      <loc>https://example.com/sitemap-pages.xml</loc>
      <lastmod>2025-01-15</lastmod>
    </sitemap>
    <sitemap>
      <loc>https://example.com/sitemap-posts.xml</loc>
      <lastmod>2025-01-14</lastmod>
    </sitemap>
    <sitemap>
      <loc>https://example.com/sitemap-images.xml</loc>
      <lastmod>2025-01-14</lastmod>
    </sitemap>
    <sitemap>
      <loc>https://example.com/sitemap-products.xml</loc>
      <lastmod>2025-01-10</lastmod>
    </sitemap>
  </sitemapindex>
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 1.4  sitemap-images.xml / sitemap-videos.xml / sitemap-news.xml
--------------------------------------------------------------------------------
WHERE   : /sitemap-images.xml, /sitemap-videos.xml, /sitemap-news.xml
FORMAT  : XML
NOTES   : Optional specialized sitemaps. Google needs images to be the actual
          <img> on the page. Video requires title, description, thumbnail,
          and player URL. News requires <news:publication>, <news:title>,
          <news:publication_date>, <news:name>, <news:language>, and only
          articles published in the last 2 days.

STRUCTURE  (IMAGE)
  -------------------------------------------------------------------------
  <?xml version="1.0" encoding="UTF-8"?>
  <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
          xmlns:image="http://www.google.com/schemas/sitemap-image/1.1">
    <url>
      <loc>https://example.com/recipes/pasta</loc>
      <image:image>
        <image:loc>https://example.com/img/pasta.jpg</image:loc>
        <image:title>Pasta with tomato</image:title>
        <image:caption>Fresh pasta, 2025</image:caption>
      </image:image>
    </url>
  </urlset>
  -------------------------------------------------------------------------

STRUCTURE  (VIDEO)
  -------------------------------------------------------------------------
  <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
          xmlns:video="http://www.google.com/schemas/sitemap-video/1.1">
    <url>
      <loc>https://example.com/watch/how-to-cook</loc>
      <video:video>
        <video:thumbnail_loc>https://example.com/thumbs/how-to.jpg</video:thumbnail_loc>
        <video:title>How to cook X</video:title>
        <video:description>Cooking lesson 1.</video:description>
        <video:content_loc>https://example.com/video/how-to.mp4</video:content_loc>
        <video:duration>600</video:duration>
        <video:publication_date>2025-01-10</video:publication_date>
      </video:video>
    </url>
  </urlset>
  -------------------------------------------------------------------------

STRUCTURE  (NEWS)
  -------------------------------------------------------------------------
  <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
          xmlns:news="http://www.google.com/schemas/sitemap-news/0.9">
    <url>
      <loc>https://example.com/news/breaking</loc>
      <news:news>
        <news:publication>
          <news:name>My News Site</news:name>
          <news:language>en</news:language>
        </news:publication>
        <news:publication_date>2025-01-15T09:00:00Z</news:publication_date>
        <news:title>Breaking: Something Happened</news:title>
      </news:news>
    </url>
  </urlset>
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 1.5  sitemap.html  (human-readable sitemap)
--------------------------------------------------------------------------------
WHERE   : /sitemap.html   (link in footer, reference in robots.txt optional)
FORMAT  : HTML
SERVED  : normal page
NOTES   : Purely for humans. Not used by search engines to index directly,
          but a good fallback and great for accessibility.

STRUCTURE
  -------------------------------------------------------------------------
  <!DOCTYPE html>
  <html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Sitemap — Example.com</title>
    <link rel="canonical" href="https://example.com/sitemap.html">
  </head>
  <body>
    <h1>Sitemap</h1>

    <!-- ===== MAIN ===== -->
    <h2>Main Pages</h2>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>

    <!-- ===== CONTENT ===== -->
    <h2>Recipes</h2>
    <ul>
      <li><a href="/recipes/pasta">Pasta</a></li>
      <li><a href="/recipes/soup">Soup</a></li>
    </ul>

    <!-- ===== LEGAL ===== -->
    <h2>Legal</h2>
    <ul>
      <li><a href="/privacy">Privacy Policy</a></li>
      <li><a href="/terms">Terms</a></li>
      <li><a href="/cookies">Cookie Policy</a></li>
    </ul>
  </body>
  </html>

 SECTION 2 · ADTECH FILES (ads.txt family)
================================================================================

--------------------------------------------------------------------------------
 2.1  ads.txt  (Authorized Digital Sellers)
--------------------------------------------------------------------------------
WHERE   : /ads.txt  (root, exact name, lowercase, ALL CAPS title case is
          technically fine but stick to lowercase)
FORMAT  : plain text, UTF-8, one record per line, comma-separated
SERVED  : Content-Type: text/plain
NOTES   : Required if you sell ad inventory programmatically.
          Third-party ad networks give you the exact lines to paste.
          One record = one authorized seller.

FORMAT OF EACH LINE
  <domain>, <publisher-account-ID>, <relationship>, [certification-authority-ID]

  relationship        = DIRECT  or  RESELLER
  certification-ID    = only if the exchange requires it (e.g. TAG ID)

STRUCTURE
  -------------------------------------------------------------------------
  # ads.txt — authorized sellers
  # Comments start with a hash.
  # Copy-paste lines from every ad network you use.

  # Google AdSense (example)
  google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0

  # Google Ad Manager (example)
  google.com, pub-1111111111111111, DIRECT, f08c47fec0942fa0

  # A reseller network (example)
  someexchange.com, 12345, RESELLER, 0000000000000000

  # Another direct network
  adnetwork.com, account-ABC, DIRECT

  # ---- You can also declare a domain you OWN ----
  # ownerdomain=example.com    ← optional, if you own multiple domains
  -------------------------------------------------------------------------

WHERE TO GET THE LINES
  · Google AdSense → “Ads.txt” in dashboard
  · Google Ad Manager → “ads.txt” section
  · Any ad network → their onboarding or dashboard
  · Never invent lines. Wrong lines can hurt monetization.

VALIDATE
  · Open https://yourdomain.com/ads.txt → must return text/plain, 200 OK.
  · It must be served by your domain, not redirected.


--------------------------------------------------------------------------------
 2.2  app-ads.txt
--------------------------------------------------------------------------------
WHERE   : /app-ads.txt  (root of the domain listed on your app store page)
FORMAT  : same as ads.txt
WHEN    : You have mobile apps (iOS/Android) and serve ads in them.
NOTES   : The developer website URL shown on the app store must point to a
          domain that hosts /app-ads.txt. Same line format as ads.txt.

STRUCTURE  (identical format to 2.1)

 3.1  manifest.webmanifest  (or manifest.json)
--------------------------------------------------------------------------------
WHERE   : /manifest.webmanifest  (root or /assets/)
LINKED  : From every HTML page:
            <link rel="manifest" href="/manifest.webmanifest">
FORMAT  : JSON
NOTES   : Makes your site installable. Served with

    "start_url": "/",

    "theme_color": "#0d3b66",
    "lang": "en",
    "dir": "ltr",
    "icons": [
      { "src": "/assets/icon-192.png",
        "sizes": "192x192",
        "type": "image/png",
        "purpose": "any" },

      { "src": "/assets/icon-512.png",
        "sizes": "512x512",
        "type": "image/png",
        "purpose": "any" },

      { "src": "/assets/icon-maskable-512.png",
        "sizes": "512x512",
        "type": "image/png",
        "purpose": "maskable" }
    ],
    "screenshots": [
      { "src": "/assets/screen-wide.png",
        "sizes": "1280x720",
        "type": "image/png",
        "form_factor": "wide" },
      { "src": "/assets/screen-narrow.png",
        "sizes": "720x1280",
        "type": "image/png",
        "form_factor": "narrow" }
    ],
    "shortcuts": [
      { "name": "Open Recipes",
        "url": "/recipes",
        "icons": [{ "src": "/assets/icon-96.png", "sizes": "96x96" }] }

KEY FIELDS

  icons       Must include 192x192 and 512x512 at minimum for installability.


--------------------------------------------------------------------------------
 3.2  service-worker.js  (or sw.js)
--------------------------------------------------------------------------------
WHERE   : /service-worker.js  (root, exact path matters)
LINKED  : From a page script — scope controls which URLs it controls:
            navigator.serviceWorker.register('/service-worker.js')
FORMAT  : JavaScript
SERVED  : Content-Type: application/javascript
NOTES   : If it's at /service-worker.js it can control ALL pages. If it's
          at /assets/service-worker.js it can only control /assets/*.
          Most people put it at root for that reason.

STRUCTURE (minimal offline cache)
  -------------------------------------------------------------------------
  // service-worker.js — minimal offline cache
  const CACHE = 'v1';
  const ASSETS = [
    '/',                 // home
    '/offline.html',     // fallback when offline
    '/assets/style.css',
    '/assets/app.js',
    '/assets/icon-192.png'
  ];

  // Install — pre-cache
  self.addEventListener('install', e => {
    e.waitUntil(
      caches.open(CACHE).then(c => c.addAll(ASSETS))
    );
    self.skipWaiting();
  });

  // Activate — clear old caches
  self.addEventListener('activate', e => {
    e.waitUntil(
      caches.keys().then(keys =>
        Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k)))
      )
    );
    self.clients.claim();
  });

  // Fetch — serve cache first, then network
  self.addEventListener('fetch', e => {
    e.respondWith(
      caches.match(e.request).then(cached =>
        cached || fetch(e.request).catch(() => caches.match('/offline.html'))
      )
    );
  });
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 3.3  offline.html
--------------------------------------------------------------------------------
WHERE   : /offline.html  (root)
FORMAT  : HTML
NOTES   : Pre-cached by the service worker. Shown when the network fails.
          Keep it tiny — no external assets (they'll fail to load too).

STRUCTURE
  -------------------------------------------------------------------------
  <!DOCTYPE html>
  <html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width,initial-scale=1">
    <title>Offline — Example.com</title>
    <style>/* INLINE styles only */
      body{ font-family:sans-serif; text-align:center; padding:4rem 1rem; }
      h1{ font-size:2rem; }
    </style>
  </head>
  <body>
    <h1>You’re offline</h1>
    <p>Check your connection and reload.</p>
    <a href="/">Try again</a>
  </body>
  </html>
  -------------------------------------------------------------------------


================================================================================
 SECTION 4 · .WELL-KNOWN FOLDER  (security / standards)
================================================================================

Every file here lives at: /<domain>/.well-known/<filename>
The folder name must be EXACTLY ".well-known" (lowercase, with dot).
Web server must serve it with correct Content-Type — do not block with
.htaccess rules. Do not put HTML files here; the expected content types are
plain text or JSON, depending on the file.


--------------------------------------------------------------------------------
 4.1  .well-known/security.txt
--------------------------------------------------------------------------------
WHERE   : /.well-known/security.txt
          (Also acceptable /security.txt for legacy)
FORMAT  : plain text
SERVED  : Content-Type: text/plain
NOTES   : RFC 9116. Tells researchers where to report vulnerabilities.
          Add a PGP or expiry if relevant.

STRUCTURE
  -------------------------------------------------------------------------
  # security.txt — security contact
  # Format: RFC 9116

  Contact: mailto:security@example.com
  # Contact: https://example.com/security/report
  # Contact: +15555550100

  Expires: 2026-01-01T00:00:00Z

  Encryption: https://example.com/pgp-key.asc
  Preferred-Languages: en, pt
  Canonical: https://example.com/.well-known/security.txt
  Policy: https://example.com/security/policy
  Hiring: https://example.com/careers
  Acknowledgments: https://example.com/security/thanks
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 4.2  .well-known/change-password
--------------------------------------------------------------------------------
WHERE   : /.well-known/change-password
FORMAT  : empty file OR HTML redirect OR 302 redirect
NOTES   : Browsers/OS use this when a password is compromised.
          Simplest: make it a redirect to /account/change-password.

STRUCTURE  (option A — redirect, works in Apache/Netlify _redirects/etc.)
  -------------------------------------------------------------------------
  / .well-known/change-password  /account/change-password  302
  -------------------------------------------------------------------------

STRUCTURE  (option B — tiny HTML file)
  -------------------------------------------------------------------------
  <!DOCTYPE html>
  <html>
  <head><meta charset="utf-8"><title>Change Password</title></head>
  <body>
    <p><a href="/account/change-password">Change your password</a></p>
  </body>
  </html>
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 4.3  .well-known/gpc.json  (Global Privacy Control)
--------------------------------------------------------------------------------
WHERE   : /.well-known/gpc.json
FORMAT  : JSON
NOTES   : Tells browsers/plugins you honour the GPC signal (California,
          Colorado, etc.).

STRUCTURE
  -------------------------------------------------------------------------
  {
    "gpc": true,
    "lastUpdate": "2025-01-15"
  }
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 4.4  .well-known/dnt-policy.txt  (Do Not Track policy)
--------------------------------------------------------------------------------
WHERE   : /.well-known/dnt-policy.txt
FORMAT  : plain text
NOTES   : Choose one of the standard DNT policies maintained by EFF.

STRUCTURE  (copy the standard text from
            https://www.eff.org/dnt-policy and paste here)
  -------------------------------------------------------------------------
  Do Not Track Compliance Policy — Version 1.0

  This domain complies with user opt-out signals as described
  in EFF's Do Not Track Policy:
  https://www.eff.org/dnt-policy

  <paste full policy text>
  -------------------------------------------------------------------------

 4.5  .well-known/apple-app-site-association   (iOS Universal Links)
--------------------------------------------------------------------------------
WHERE   : /.well-known/apple-app-site-association
FORMAT  : JSON (NO .json extension, no BOM)
SERVED  : Content-Type: application/json  (a bare file is fine; Apple reads it)
WHEN    : You have an iOS app and want example.com/app/* to open in the app.

STRUCTURE
  -------------------------------------------------------------------------

    "applinks": {
      "apps": [],
      "details": [
        {
          "appID": "TEAMID.com.example.app",
          "paths": [
            "/recipes/*",
            "/posts/*",
            "NOT /admin/*"
          ]
        }
      ]
    },
    "webcredentials": {
      "apps": [ "TEAMID.com.example.app" ]
    },
    "appclips": {
      "apps": [ "TEAMID.com.example.app" ]
    }
  }
  -------------------------------------------------------------------------


--------------------------------------------------------------------------------
 4.6  .well-known/assetlinks.json   (Android App Links / Digital Asset Links)
--------------------------------------------------------------------------------
WHERE   : /.well-known/assetlinks.json
FORMAT  : JSON
SERVED  : Content-Type: application/json
WHEN    : You have an Android app and want links to open in the app.

--------------------------------------------------------------------------------
 4.7  .well-known/mta-sts.txt  (email, advanced)
--------------------------------------------------------------------------------
WHERE   : /.well-known/mta-sts.txt

--------------------------------------------------------------------------------
 7.1  .htaccess  (Apache)
--------------------------------------------------------------------------------
WHERE   : /.htaccess  (root or per-folder; inherits recursively)
SERVED  : never (Apache reads it)
NOTES   : Apache-only. Ignored by Nginx, Netlify, Vercel.
          Any syntax error = 500 for the whole directory tree.

STRUCTURE  (annotated; delete what you don't need)
  -------------------------------------------------------------------------
  # ---- 1. Force HTTPS ----
  RewriteEngine On
  RewriteCond %{HTTPS} !=on
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

  # ---- 2. Force non-www ----
  RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
  RewriteRule ^ https://%1%{REQUEST_URI} [L,R=301]

  # ---- 3. Serve index.html for clean URLs ----
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^([^\.]+)$ $1.html [NC,L]

  # ---- 4. Custom error pages ----
  ErrorDocument 404 /404.html
  ErrorDocument 500 /500.html
  ErrorDocument 403 /403.html

  # ---- 5. Security headers (add these) ----
  <IfModule mod_headers.c>
    Header always set X-Content-Type-Options "nosniff"
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Permissions-Policy "geolocation=(), microphone=()"
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
    # Header always set Content-Security-Policy "default-src 'self'; ..."
  </IfModule>

  # ---- 6. Compression ----
  <IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/css application/javascript \
                                application/json image/svg+xml
  </IfModule>

  # ---- 7. Caching ----
  <IfModule mod_expires.c>
    ExpiresActive On
    ExpiresByType image/png  "access plus 1 year"
    ExpiresByType image/jpg  "access plus 1 year"
    ExpiresByType text/css   "access plus 1 month"
    ExpiresByType application/javascript "access plus 1 month"
    ExpiresByType text/html  "access plus 1 hour"
  </IfModule>

  # ---- 8. Deny hidden files ----
  <FilesMatch "^\.">
    Require all denied
  </FilesMatch>

  # ---- 9. Force downloads for certain types (optional) ----
  # AddType application/octet-stream .pdf

  # ---- 10. Correct MIME for .webmanifest ----
  AddType application/manifest+json .webmanifest
  AddType application/xml .xml
  AddType text/plain .txt

  # ---- 11. Redirects ----
  # Redirect 301 /old-page /new-page
  -------------------------------------------------------------------------

 7.2  web.config  (IIS / Windows Server)
--------------------------------------------------------------------------------
WHERE   : /web.config

STRUCTURE
  -------------------------------------------------------------------------
  <?xml version="1.0" encoding="UTF-8"?>
  <configuration>
    <system.webServer>
      <rewrite>
        <rules>
          <!-- Force HTTPS -->
          <rule name="HTTPS" stopProcessing="true">
            <match url="(.*)" />
            <conditions>
              <add input="{HTTPS}" pattern="^OFF$" />
            </conditions>
            <action type="Redirect"
                    url="https://{HTTP_HOST}/{R:1}"
                    redirectType="Permanent" />
          </rule>
          <!-- Clean URLs -->
          <rule name="HTML extension" stopProcessing="true">
            <match url="^(.*)$" />
            <conditions>
              <add input="{REQUEST_FILENAME}.html" matchType="IsFile" />
            </conditions>
            <action type="Rewrite" url="{R:1}.html" />
          </rule>
        </rules>
      </rewrite>

      <httpErrors>
        <remove statusCode="404" />
        <error statusCode="404" path="/404.html" responseMode="ExecuteURL" />
        <remove statusCode="500" />
        <error statusCode="500" path="/500.html" responseMode="ExecuteURL" />
      </httpErrors>

      <httpProtocol>
        <customHeaders>
          <add name="X-Content-Type-Options" value="nosniff" />
          <add name="X-Frame-Options" value="SAMEORIGIN" />
          <add name="Referrer-Policy" value="strict-origin-when-cross-origin" />
        </customHeaders>
      </httpProtocol>

      <staticContent>
        <mimeMap fileExtension=".webmanifest"
                 mimeType="application/manifest+json" />
      </staticContent>
    </system.webServer>
  </configuration>
  -------------------------------------------------------------------------

 11.7  Cookie consent banner snippet
--------------------------------------------------------------------------------
WHERE TO PASTE : Just before </body> of every page (or load from external JS).
NOTES         : Must load BEFORE any tracking script that sets cookies.
                For strict GDPR compliance, load analytics ONLY after consent.

STRUCTURE  (skeleton — replace with your CMP library)
  -------------------------------------------------------------------------
  <script>
    // Load this BEFORE analytics.
    window.dataLayer = window.dataLayer || [];
    function gtag(){ dataLayer.push(arguments); }

    // Default = denied for EU users
    gtag('consent', 'default', {
      'ad_storage': 'denied',
      'analytics_storage': 'denied'
    });

    // When user clicks "Accept", update consent
    window.grantConsent = function(){
      gtag('consent', 'update', {
        'ad_storage': 'granted',
        'analytics_storage': 'granted'
      });
      localStorage.setItem('cookie-consent', 'granted');
    };
  </script>

 SECTION 14 · STEP-BY-STEP: HOW TO ADD A SPECIAL FILE
================================================================================

STEP 1 · Choose which file you need from the table above.
STEP 2 · Create a plain text file with that EXACT NAME (case-sensitive).
STEP 3 · Paste the STRUCTURE template from this document.
STEP 4 · Replace placeholders (example.com, G-XXXX, etc.).
STEP 5 · Upload to the correct location:
           · FTP / SFTP clients (FileZilla, Cyberduck):
               → connect, upload to the root folder (usually public_html/,
                 htdocs/, or www/)
           · cPanel:
               → File Manager → upload
           · GitHub Pages:
               → commit to the branch GitHub serves (often main or gh-pages)
           · Netlify / Vercel / Cloudflare Pages:
               → commit to the repo; the config file is read at build
           · WordPress (if you use it):
               → some files (ads.txt, robots.txt) have admin UIs;
                 others go in the site root via FTP or a plugin
STEP 6 · Verify in a browser:
           · robots.txt  → https://yourdomain.com/robots.txt
           · ads.txt     → https://yourdomain.com/ads.txt
           · sitemap.xml → https://yourdomain.com/sitemap.xml
           · security.txt→ https://yourdomain.com/.well-known/security.txt
           All must return 200 OK, correct Content-Type, no redirect.
STEP 7 · Validate:
           · robots.txt  → GSC → Robots.txt Tester
           · sitemap.xml → GSC → Sitemaps
           · ads.txt     → https://adstxt.guru (or IAB validator)
           · security.txt→ https://securitytxt.org validator
           · manifest    → Chrome DevTools → Application → Manifest
           · PWA         → Chrome DevTools → Lighthouse → PWA audit
STEP 8 · Submit in Google Search Console and Bing Webmaster Tools.
STEP 9 · Add a plain-URL link to the file in your own notes/README so you
         remember where it is 6 months from now.
