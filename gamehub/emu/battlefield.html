Briefing

What you are deploying into

Battlefield is built around one idea: war at scale. Two teams fight over a map cut into capture points, and every point you hold bleeds the enemy of their ticket count. You are not locked to a single lane — you pick a kit, you pick a spawn, and you push whichever objective matters most right now.

What separates it from a standard shooter is combined arms. Infantry, armour and air all share the same battlefield. A squad of riflemen can hold a flag until a tank rolls in; a gunship can clear that tank's approach; a single engineer can turn the whole exchange around. Nothing wins alone, and nothing is wasted — every class, every vehicle and every spawn point exists to break a stalemate somewhere on the map.

Scale

Wide maps with multiple capture points, real front lines and room to flank.

Combined arms

Infantry, tanks, transports and air support fighting in the same space.

Kits

Assault, engineer, medic and support roles — each one changes how a push works.

Squads

Spawn on your squad, share the objective, and keep the pressure on.

Destruction

Cover is temporary. Buildings and terrain take damage and reshape the fight.

Conquest

Hold the majority of flags and drain the enemy ticket pool to win.

How this deployment works

The game runs inside an emulation layer that renders through WebGPU and stores the game package in your browser's cache. The first deployment downloads the full asset set — expect it to take a while on a slower connection. Every deployment after that is served from cache and starts in seconds.

Because the emulator needs cross-origin isolation, this page registers a small service worker on your first visit and reloads itself once to activate it. That reload is expected — do not close the tab.

Performance Protocol

Do these three things before you judge the frame rate
  1. 1
    Make Chrome use your fast GPU. The emulator renders with WebGPU, and Chrome does not always pick your discrete card on its own. On Windows open Settings → System → Display → Graphics, add Chrome to the app list and set it to High performance, then restart the browser. Verify it worked by opening chrome://gpu — your dedicated GPU should be listed first.
  2. 2
    Close other tabs and apps. Battlefield streams a large asset set into memory and keeps it there. Every spare tab holds GPU memory and CPU time you want back. Discord overlays, recording software and hardware monitors are the usual frame-rate suspects.
  3. 3
    Keep FPU: Relaxed on. It is already set to Relaxed by default — leave it exactly there. It trades a meaningless amount of floating-point precision for a measurable frame-rate gain.

Troubleshooting

The usual suspects, in order of likelihood
The game never loads and the reticle keeps spinning

Almost always this is cross-origin isolation not being active yet. The page reloads itself once on first visit to activate the service worker — if you closed that tab too early, just reload the page manually.

Check the Cross-origin isolation card above. It must be green before the emulator can start. If it stays amber, your browser or an extension is blocking service workers — try a normal (not private) window with extensions disabled, or use Open in new tab.

It loads but the frame rate is terrible

Run the three steps in the Performance Protocol above. In particular, confirm Chrome is actually using your discrete GPU: open chrome://gpu and check that your dedicated card is the first adapter listed. If it says SwiftShader or software, Chrome has fallen back to CPU rendering and nothing else will fix the frame rate until that is corrected.

Then close every other tab and background app, and make sure the game is running in a normal window rather than a throttled background one.

Black screen, but the page thinks it loaded

Click once inside the black area to give the game focus — some builds render their first frame only after receiving input. If that does nothing, press Redeploy.

If it happens repeatedly, open chrome://gpu and make sure WebGPU is not disabled or blocklisted. Updating Chrome usually resolves it.

Controls do nothing

The game only receives input while it has focus. Click directly inside the game area once, then try again. If the mouse cursor is captured, press Esc to release it and click back in.

For a controller, connect it before the game finishes loading and press a button once so the browser registers it.

No sound

Browsers block audio until you interact with the page. Click inside the game once. Also check that the tab is not muted — right-click the tab and confirm Unmute site is not showing.

Why does the page reload itself the first time?

The emulator needs SharedArrayBuffer, which browsers only expose to cross-origin isolated pages. A small service worker (coi-serviceworker.js) adds the required COOP / COEP headers, and the page reloads once so those headers apply. It is a one-time step per browser.

Does the game need to download every time?

No. The first deployment downloads the full package into your browser cache. After that, launches are served from cache and start in seconds. Clearing site data will force a fresh download.
